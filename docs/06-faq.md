# 06 · 常见问题

## 为什么不直接合并会话？

三个理由：

1. **路由**：合并后一条回复不知道发回哪个平台，容易双发
2. **膨胀**：多渠道消息混在一起，上下文迅速超限
3. **隐私**：群聊（有第三人）的内容会流进私聊

合并会话是"用一个问题换三个问题"。HCR 选择不合并，只交接。

## 这跟 RAG 有什么区别？

RAG 解决"从知识库里找相关内容"。
HCR 解决"两个渠道之间怎么算同一段对话"。

RAG 可以用在"屋"的内部；但走廊不是检索问题，是**调度问题**。

## 会不会出现"她记得太多"？

会，如果全量注入。所以 HCR 要求：

- 室里只放最近 N 轮
- 屋按当前话题检索，不是全量
- 走廊只带线索，不带历史

**记得多不等于像人。人也会忘。**

## 群聊怎么处理？

群聊是"有第三人的房间"：

```
共享屋（长期记忆）
不共享廊（对话线索）
```

她可以记得"这个群里聊过什么"，但不能把群里的对话当成私聊的延续。

## 需要向量数据库吗？

不需要。

最小实现用三个 JSON 文件 + 关键词重合度就能跑通。
记忆量超过几万条再考虑向量检索。

## 一个角色、多个用户怎么办？

HCR 假设"一个角色、一个主要对话者"。
多用户场景需要在屋和廊之上再加一层**用户隔离**（每个用户一份屋和廊），
这不在 v0.1 的范围内。

## 为什么叫"屋·廊·室"？

因为它需要一个能被人立刻记住的直觉：

> 同一个屋檐下，各房间独立，走廊相连。

架构图往往记不住，但"她在哪个房间"一听就懂。
