# 09 · 怎么接入一个新渠道

HCR 把渠道当作「窗口」。加一个窗口，不需要改模型，只需要写一个适配器。

## 三步

### ① 收

把平台的消息归一化成统一结构：

```json
{ "from": "owner | her", "via": "channel-id", "text": "…", "at": 1793364600000 }
```

### ② 发

把回复发回**触发这次思考的那个渠道**。
注意：不是"默认渠道"，是"这条消息来自哪，就回哪"。

### ③ 登记

把渠道 id 加进走廊的渠道列表，它的消息就会自动参与交接。

```
屋       不用改
廊       不用改（只是多了一个 via 值）
室       新增一个
```

## 关键：先给渠道分类

同一个平台，可能同时存在「私密场合」和「公开场合」：

| 场合 | 例子 | 进不进廊 |
|---|---|---|
| 私聊 / 私信 | IM 私信、站内信 | ✅ 进 |
| 群聊 / 评论区 | 群、评论、弹幕 | ❌ 不进（只进屋） |
| 广播 | 动态、朋友圈 | ❌ 不进 |

**分错了，感觉就全错。**
在广场上说的话，不该被当成两个人之间的悄悄话。

## 检查清单

接入前问自己：

- [ ] 这个渠道是私密还是公开？
- [ ] 它的延迟是多少？（交接窗口要比延迟大）
- [ ] 它会不会被风控？触发时的降级行为是什么？
- [ ] 它需要哪些凭证？存在哪？会不会进备份？
- [ ] 出问题时，用户会不会知道？（告警）

## 一个反直觉的提醒

**每加一个渠道，系统的脆弱程度是叠加的，不是平摊的。**

三个渠道，任意一个坏了，用户感受到的都是"她出问题了"。
所以在接入之前，先问：**这个渠道带来的价值，值不值得多一份维护成本？**
