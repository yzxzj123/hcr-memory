# 03 · 走廊：交接规则

走廊是 HCR 里唯一"有状态、有规则"的一层。它不做记忆，只做交接。

## 六条规则

### R1 · 时间窗

跨室只在**有限时间内**算"同一段对话"。

```
建议：6 小时
超过 → 视为新的一段，允许重新开场
```

为什么不是无限：人会睡觉、会隔天再聊。无限时间窗会让角色永远"接着昨天的半句话"，很怪。

### R2 · 禁止重新打招呼

交接后的一小段时间内（建议 15 分钟），角色**不得**使用开场语：

```
禁止：在吗 / 怎么了 / 有事吗 / 你好
```

这是最破坏"同一个人"感觉的一条。**目标不是"记得内容"，是"不把继续当成开始"。**

### R3 · 悬问接续

记录角色问过、用户还没回答的问题。换室后**主动接着问**。

```
A 室：角色：拍没拍下来？
用户：……（没答，切走了）

B 室：角色：你还没说拍没拍呢
```

判定"答没答"不能靠模型猜，用规则：
- 用户下一条消息落在问题之后 2 小时内 → 视为已答
- 否则过期失效

### R4 · 话题栈

不是"最近 N 句"，而是**带层级的话题**：

```
话题栈：
  [当前] 那只猫
  [上一] 晚饭
  [搁置] 他的工作
```

切换话题时保留上一层；隔几句还能接回去（"你刚才说累，是加班吗"）。

### R5 · 平台署名

交接过来的内容必须**标明来源**，且角色不能混淆：

```
注入示例：
【他刚在 A 平台跟你聊到一半，就过来了】直接接着聊，别重新打招呼。
【你们正说到】
  他（A 平台）：我刚看见一只一只很特别的猫
  你（A 平台）：在哪看见的呀
```

最后那句"（A 平台）"不是给用户看的，是给模型的约束：
**别把另一个平台说过的话，当成这个平台说过的。**

### R6 · 群聊隔离

有第三人在场的房间，**永不并入走廊**。

```
私聊 A ─┐
私聊 B ─┼→ 共用屋与廊
私聊 C ─┘
群聊   ──→ 独立，只共享屋，不共享廊
```

原因有两个：隐私（别人的话不该流到私聊）、上下文（群聊节奏快，会淹没私聊线索）。

## 走廊交付什么（以及不交付什么）

**交付**

```
· 最近 10 轮原话（带平台标签、时间戳）
· 3 层话题栈
· 未回答的问题
· 未兑现的承诺
· 一条交接提示（含"别重打招呼"）
```

**不交付**

```
· 完整历史（屋里有，按需检索）
· 另一个平台的长期偏好（避免串味）
· 群聊内容
```

## 一个容易踩的坑

走廊带的是**摘要 + 原话**两层，缺一不可。

只有摘要：模型会忘细节（"聊了日常"丢掉了猫）。
只有原话：更早的铺垫丢了。

```
【最近在 A 平台你们聊到】他看见一只一只很特别的猫，问拍没拍下来。
【A 平台最后几句原话】
  他：我刚刚看见了一只大眼睛一只很特别的猫
  你：那个花纹很好认啊
  你：你在哪看见的呀 拍没拍下来
```
