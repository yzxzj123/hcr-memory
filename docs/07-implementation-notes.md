# 07 · 实现笔记（不含具体代码）

## 落地时的四个判断点

### 1. 走廊在什么时候渲染

```js
if (当前渠道 !== 上次渠道 && 时间差 < 时间窗) {
  注入交接提示 + 最近 N 轮 + 悬问
}
```

**注意**：交接提示用一次就该失效（清空 switchedFrom），
否则之后每句话都会带上"他刚从 X 过来"，很怪。

### 2. 悬问的自动判定

不要用模型判断"这个问题答没答"，成本高且不稳。
用规则：

```
用户下一条消息在问题后 2 小时内出现 → 标记已答
超过 2 小时 → 过期
```

误判的代价很低：最多是没追问一次，或者多问一次。

### 3. 平台署名必须强制

注入时给每条跨渠道消息打上"（X 平台）"。
少了这一条，模型会把另一个平台说过的话当成这个平台说过的——
表现出来就是"串台"，比你想象的更容易发生。

### 4. 摘要和原话都要带

只带摘要会丢细节（"聊了日常"）；
只带原话会丢铺垫。
两层一起给，token 成本仍然很低（十几句而已）。

## 成本估算

```
每轮额外注入：约 300–500 token
按每天 200 轮算：约 6–10 万 token/天
```

对多数模型来说，这是几分钱的事。

## 迁移路径

如果你的系统现在是"每个渠道一个会话 + 一份共享记忆"：

1. 先加**摘要交接**（最简单，一天）
2. 再加**原话交接**（细节立刻回来）
3. 最后加**悬问与话题栈**（连续性完整）

三步都可以独立上线，任何一步坏了都能关掉。
