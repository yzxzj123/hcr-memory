# 01 · 问题：换平台就换个人

## 现象

一个 AI 角色同时接入多个聊天平台（比如 即时通讯平台 A 和 B）。
用户在 A 平台聊到一半，切到 B 平台继续，会遇到：

```
A 平台：  用户：我刚看见一只一只很特别的猫
          角色：在哪看见的呀 拍没拍下来

（切到 B 平台）

B 平台：  角色：在吗？怎么了？
                ↑ 重新打招呼，像换了个人
```

更隐蔽的三种断裂：

1. **重新开场**：把"继续聊"当成"新对话"
2. **悬问丢失**：它问过、用户还没答的问题，换平台后不记得
3. **话题断层**：只记得最近几句，前面的铺垫没了

## 根因：会话同时承担了两种职责

大多数聊天机器人把两件事塞进了同一个对象：

```
Session = 记忆（聊过什么） + 通道（发到哪）
```

因为"通道"不同，就不得不开两个 Session；
因为"记忆"跟着 Session 走，人就跟着裂开了。

**这不是记忆容量问题，是抽象错了。**

## 已有的尝试与盲区

| 方案 | 解决了什么 | 留下的盲区 |
|---|---|---|
| MemGPT / Letta | 单 agent 上下文不够长（分层记忆） | 不处理多渠道 |
| LangGraph | thread（会话）+ store（长期记忆）分离 | 不定义跨线程的交接语义 |
| Mem0 / Zep | 记忆的读写接口、时间有效性 | 不处理身份同一性 |
| SparkCore | 多渠道伴侣、五层记忆 | 分层而非分室，没有"交接"这一层 |
| ai-continuity-framework #49 | **准确描述了这个问题** | 提议阶段，未见公开的实现方案 |

最后一条值得单独说：该 RFC 的原文是——

> 在不同渠道聊天时，体验是割裂的。同一个模型、同样的记忆，但感觉不一样。
> 用户说："那个渠道不像你。"

它把根因归为：系统提供了情节记忆，但没有**工作上下文**——
"我们正聊到哪、共同的默契、对话的惯性"。

**HCR 是给这个"工作上下文"找一个位置的另一种尝试。**
