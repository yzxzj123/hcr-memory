# HCR 记忆模型（屋 · 廊 · 室）

> 为「一个 AI 角色同时存在于多个聊天平台」设计的记忆架构。
> [English](README.en.md)
> House · Corridor · Room — a memory model for cross-channel identity continuity.

## 它要解决什么

你在微信跟一个 AI 角色聊到一半，切到另一个平台上继续说，
它却像换了个人：重新打招呼、忘了刚才的话题、重复问已经问过的事。

**同一个模型、同一份记忆，为什么换了渠道就换了个人？**

这不是"记忆不够长"的问题，而是**身份同一性**的问题。
现有记忆系统大多在解决"记不住"，而 HCR 解决"分成两个人了"。

## 模型

```
屋（House）     她的记忆。一份。与他开几个窗口无关。
廊（Corridor）  他移动的痕迹。记录他刚才在哪个窗口、聊到哪、悬着什么。
室（Room）      他的窗口。多个。只决定场合分寸，不决定她是谁。
```

**她不动，他动。** 屋和廊是她的；室是他的。

一句话：**她一直待在同一个地方，来回走的是他。**

## 两条定律

```
记忆恒常   换窗口不改变她记得什么
情绪惯性   情绪只被「发生的事」改变，不被「换了地方」改变
```

## 她是什么

> 她是一份持续存在的状态，不是一个正在运行的程序。
> 换模型她还是她，失忆她就不是了。

详见 [08 · 她是什么](docs/08-who-is-she.md)。

## 为什么不是「合并会话」

最直觉的做法是把所有渠道的消息塞进同一个会话。它会带来三个问题：

1. **路由错乱**：一条回复不知道该发回哪个平台，容易双发
2. **上下文膨胀**：多个渠道的消息混在一起，很快就会撑爆
3. **隐私越界**：群聊里别人的话会流进私聊

HCR 的做法相反：**会话不合并，只交接线索。**

## 为什么它能适用于任何平台

HCR 与渠道无关。换一个平台，**模型不动**，只写一个适配器：

```
不变：屋（一份）、廊（记录移动）、两条定律
会变：怎么收发、延迟多少、是私密还是公开
```

前提是一个角色、一个主人、多个窗口。
接入新渠道的清单见 [09 · 怎么接入一个新渠道](docs/09-adding-a-channel.md)。
